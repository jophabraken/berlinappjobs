# Site build

Everything on berlinappjobs.com is generated from this folder. GitHub Pages serves the repo root, and
`robots.txt` blocks `/_build/` from crawlers.

```
python3 _build/build_all.py        # rebuilds guides, company/city pages, job pages, sitemaps and the homepage
```

Needs Python 3.10+ and `pip install bleach`. It takes about 5 seconds.

| Path | What it is |
|---|---|
| `data/board_data.js` | Job board data: companies, jobs, charts, icons. Refreshed from the companies' hiring systems. |
| `data/descriptions.json.gz` | Full job descriptions from the hiring-system feeds (for `/job/` pages) |
| `data/guides_data.js` | Generated by `build_seo.py` from `articles_src*.py` (in-app guides tab) |
| `data/geo_data.js` | Germany map outline |
| `data/jobpages_map.json` | Generated: hiring-system URL → our `/job/` page |
| `templates/board.html` | The job board app (HTML + CSS + JS). `build_home.py` splits it into `index.html`, `assets/app.js` and `assets/data.js` |
| `articles_src.py`, `articles_src2.py` | Guide articles (content + metadata) |
| `build_seo.py` | Guide pages, guides hub, `robots.txt`, the in-app guides data |
| `build_programmatic.py` | Company pages, city and role × city pages, `sitemap.xml` |
| `build_jobpages.py` | One page per job with JobPosting markup, `sitemap-jobs.xml` |
| `build_home.py` | The homepage, with pre-rendered numbers and job links for crawlers |
| `paths.py` | Paths and the build date (the date of the last data refresh, not today) |

Rules:
- Edit sources here, never the generated HTML. The next build overwrites it.
- Job pages carry `validThrough` = fetch date + 30 days, so refresh the data at least every 3–4 weeks.

## Automation

- `.github/workflows/build-site.yml`: when `_build/**` changes on `main`, it rebuilds the site, runs
  `check_site.py`, commits the generated pages, pings IndexNow and asks GitHub Pages to publish. So a pull
  request only needs to change the sources in `_build/`.
- `.github/workflows/check-pr.yml`: every pull request is built in a scratch folder and checked. A red X
  means don't merge.
- `check_site.py` checks for one title, description and canonical per page, broken internal links, sitemap URLs
  without a page, homepage size, and duplicate titles (warning only).
